### Находки

- **[P2] `status.md:44` — «бесконечный» режим имеет неограниченный рост объектов и слушателей.**  
  Каждая волна создаёт новые `Enemy` (`src/main.js:182`), но `Enemy.die()` лишь выставляет `active=false` (`src/entities/Enemy.js:72-75`), не удаляя объект из `scene.enemies`. Боссы аналогично остаются в группе, а каждый экземпляр добавляет замыкание `SHUTDOWN` (`src/entities/BossBase.js:56`). В бесконечном цикле число inactive-объектов и shutdown-слушателей постоянно растёт. Сам `status.md:55` признаёт этот долг, поэтому новая декларация «Игра полная» внутренне противоречива. Phaser не удаляет inactive-членов группы автоматически — для этого нужны `remove`/`destroy` либо настоящее переиспользование пула: [Phaser 3.90 Group API](https://docs.phaser.io/api-documentation/3.90.0/class/physics-arcade-group).

- **[P2] `.planning/.continue-here.md:20` — обязательная Pause ошибочно превращена в необязательный “вопрос владельцу”.**  
  `docs/SPEC.md:774` и `:789` явно требуют `Game ⇄ Pause`, Esc, оверлей и заморозку мира. Handoff направляет последний тикет FUN-26 преимущественно на 15 пунктов §16, где Pause случайно отсутствует, и допускает закрытие проекта без требования §14. Нужно либо включить Pause в обязательную приёмку M9, либо формально изменить SPEC решением владельца.

- **[P3] `status.md:38` — неверно указан коммит NOTICE.**  
  `3c05323` добавляет только `LICENSE`; `NOTICE` добавлен отдельным коммитом `a097fe8`. Текущая формулировка ломает трассируемость handoff.

- **[P3] `.planning/.continue-here.md:33` — неверно описан API скоринга.**  
  `WaveDirector.loadWave()` выставляет `scoring.cycle` (`src/systems/WaveDirector.js:80-82`), а `cycleMultiplier` — read-only getter, который возвращает минимум `1` (`src/systems/Scoring.js:124-127`). Формулировка «cycleMultiplier (0=кампания), выставляет WaveDirector» может привести следующего разработчика к записи в getter.
