Находки:

- [P2] `CLAUDE.md:99` — `diff ... || echo ...` превращает несовпадение в exit 0. Если конкурентная перезапись остаётся схемно валидной, последний валидатор тоже проходит, и процедура объявляет успех после обнаруженного clobber. Verify-after-write не fail-closed. **Блокирует принятие заявленного гейта.**

- [P2] `CLAUDE.md:92` — `mktemp -t state-body` непереносим: GNU `mktemp` отвечает `too few X's`. Поскольку ошибка не останавливает сниппет, `tmp=""`, `back=".back"`, валидатор переключается на stdin, а `trap` способен удалить посторонний файл `.back`. Нужен явный шаблон `state-body.XXXXXX` и немедленный выход при ошибке.

- [P3] `CLAUDE.md:93` — `$back` не создаётся через `mktemp`, а предсказуемо выводится из имени первого файла. На общем `/tmp` это оставляет окно pre-create/symlink; кроме того, редирект на строке 98 при обычном `umask 022` создаёт файл с правами 0644. `chmod 600` защищает только `$tmp`. **Нарушает обещание “0600, без следов”.**

- [P3] `CLAUDE.md:98` — `gh ... --jq .body` является форматированным, а не побайтовым экспортом: реализация GitHub CLI выводит строковый результат через `fmt.Fprintln`, добавляя перевод строки. Поэтому `diff` может сообщить clobber только из-за завершающего LF. Нужен вывод тела без форматирующего разделителя. [Исходник GitHub CLI/go-gh](https://raw.githubusercontent.com/cli/go-gh/v2.13.0/pkg/jq/jq.go)

- [P3] `CLAUDE.md:103-104` — утверждение «проверка проходит по пустому телу» неверно. Валидатор читает stdin, но пустой stdin завершается с кодом 1 из-за отсутствующих обязательных полей; пройти может только посторонний **валидный** stdin. **Документация и реальное fail-closed поведение расходятся.**
